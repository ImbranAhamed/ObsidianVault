
No need to define the backing fields 
We may need just to get and set the data

**Without Auto-Props**:

You'll end up in verbose code for simple get and set property

// An Employee Car type using standard property
// syntax.
class Car
{
   private string carName = "";
   public string PetName
   {
     get { return carName; }
     set { carName = value; }
   }
}


**With Auto-props**:

class Car
{
   // Automatic properties! No need to define backing fields.
   public string PetName { get; set; }
   public int Speed { get; set; }
   public string Color { get; set; }
}



When you define auto props in a class, use it across the methods, constructor, .. class
and you'll not able to access the compiler generated backing field inside any statement.

**The backing fields auto-generated by the compiler are set to the default values**

class Garage
{
  // The hidden int backing field is set to zero!
  public int NumberOfCars { get; set; }
  
  // The hidden Car backing field is set to null!
  public Car MyAuto { get; set; }
}

and also initialized via **field initialization syntax:**

public string Name{get; set;} = "Imran";
